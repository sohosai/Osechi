# ログ設計・運用方針

ユーザー環境で問題が発生した際、迅速に状況把握と原因特定を行えるようにするため、アプリケーション全体で一貫したログ出力を行います。


## ログシステムの特徴

Osechiのログシステムには以下の特徴があります。

- **ファイル保存と標準出力**: ログはデバッグ用の標準出力（ターミナル）に表示されると同時に、 `./logs` ディレクトリ以下にログファイルとして自動的に保存されます。
- **非ブロッキング設計**: ログ出力ライブラリとして [tracing](https://docs.rs/tracing/latest/tracing/) を採用し、非同期のファイル書き込みを行っています。これにより、UIスレッドや描画ループをブロックしません。

## 開発上の注意点

Osechiでは、関数の呼び出し履歴や引数を自動的に記録する「トレース（`#[instrument]`）」機能は原則として使用しません。
シンプルに「特定のイベントが発生したこと」や「エラーが発生したこと」を記録する**通常のログ出力のみ**を使用します。

### 1. `#[instrument]` は使用しない
- 関数の上部に `#[instrument]` マクロを付与した自動トレースは行わないでください。

### 2. 基本のログマクロのみを使用する
- ログの記録には、`error!`, `warn!`, `info!`, `debug!` マクロのみを使用します。
- **コード例**:
  ```rust
  // ログマクロを直接呼び出して、シンプルなメッセージと必要な変数を出力します
  tracing::info!("Input {} changed: {} -> {}", idx + 1, old_name, new_name);
  ```

## ログレベルの使い分け

| レベル | マクロ | 主なユースケースと具体例 |
| :--- | :--- | :--- |
| **ERROR** | `error!` | **アプリケーションの動作維持が不可能な致命的エラー**<br>・ファイル読み書きや初期化の致命的失敗<br>・スレッドのパニック、回復不能なI/Oエラー |
| **WARN** | `warn!` | **致命的ではないが、異常な状態や注意が必要な状況**<br>・一時的なストリーム切断、フレームドロップの発生<br>・設定ファイルのパース失敗時のデフォルトフォールバック<br>・推奨されない設定や状態での動作開始 |
| **INFO** | `info!` | **システムの重要な状態遷移やライフサイクルイベント**<br>・アプリケーションの起動/正常終了<br>・ユーザー操作による重要なステート変更（例: 入力ソースの変更）<br>・接続デバイスの再スキャン実行の開始 |
| **DEBUG** | `debug!` | **開発時の動作確認や詳細なトラブルシューティング用情報**<br>・取得したフレームサイズやテクスチャのサイズ、フレームレートの情報<br>・内部の細かなイベントハンドリングや状態遷移 |
